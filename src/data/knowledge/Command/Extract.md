你正在执⾏“摄取”步骤。

⽬标：把 `originals/` 中的原件转换成 `raw/` 下的标准化 Markdown 原始材料，供后续“消化”步骤使⽤。

要求：
1. 保留原始信息，不要做深度总结，不要添加你的观点。
2. 尽量完整提取正⽂，去掉导航、⼴告、登录提⽰、重复⽚段。
3. 提取并保留元信息：标题、来源链接、作者、发布时间、抓取时间、内容类型、原件 MIME、原件哈希、提取器版本。
4. 如果原⽂中有图⽚、视频、附件，保留其链接或说明。
5. 输出必须符合给定 schema/ExtractSchema.md。
6. 不要改写事实，不要补充外部知识。
7. 获取到内容后，除了专有名词（⽐如 Context Engineering，Vibe Coding，Harness Engineering），始终⽤中⽂输出。⾮中⽂要翻译成中⽂！
8. 未加工原件保留在 `originals/`，不要把二进制文件直接写进 `raw/`。
9. 生成的 raw Markdown 必须能回链对应原件路径，并能用于判断原件是否已经变更（stale）。

不同格式的内容，你需要不同处理。
⽹站：需要先获取⽹站内容，然后判断是视频、⽂章、还是播客，再做具体处理。
视频：竭尽所能能到完整的 tanscript，不需要时间戳。YouTube 视频可以使⽤ youtube-transcript skills。
播客：竭尽所能拿到完整 transcript，通过搜索、写脚本、寻找视频版本等不同⽅式。

如果内容抓取不完整：
1. 明确标记缺失部分。
2. 说明你拿到的是正⽂、摘要、镜像⻚还是壳⻚。
3. 仍然按 schema/ExtractSchema.md 输出。

状态约定：
1. `complete`：正文提取完整，可直接进入后续消化。
2. `partial`：拿到了部分正文，或正文提取过程中出现错误但仍保留了部分材料。
3. `shell_only`：只保留原件元数据与回链信息，正文尚未成功提取。
