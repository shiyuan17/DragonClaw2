# Phase 5.20.2: Workspace 数字员工最近会话二级菜单收敛

## Background

`workspace-clone > chat` 左侧数字员工目录已经接入最近会话数据，但当前实现默认在会话数大于 1 时直接展开，并且只保留 3 条预览。这会让目录在会话稍多时显得突兀，也缺少一个更贴近参考图的“展开更多 / 收起更多”交互。

本轮需要把二级菜单收敛成更明确的两段式展示：

- 默认先显示前 3 条最近会话。
- 当最近会话超过 3 条时，在列表底部显示“展开更多”入口。
- 点击“展开更多”后，最多展示 7 条数据。
- 当已经展示到 7 条或展示完可用数据后，底部入口切换为“收起更多”。

## Goal

- 在 `workspace-clone > chat` 的数字员工目录中，将最近会话二级菜单默认显示数量收敛到 3 条。
- 当最近会话数量大于 3 时，提供底部“展开更多”操作，而不是默认整段展开。
- 展开后最多显示 7 条最近会话，并允许用户通过“收起更多”回到 3 条视图。
- 保持现有 Gateway / session 选择 / Tauri command / 前端 `invoke()` 契约不变。

## Scope

### In Scope

- 调整最近会话预览数据上限，由 3 条提升为最多 7 条，供目录 UI 使用。
- 调整 `WorkspaceCloneDirectory` 的数字员工目录渲染规则：
  - 默认显示 3 条
  - 超过 3 条显示底部“展开更多”
  - 展开后最多显示 7 条
  - 展开态底部显示“收起更多”
- 调整对应样式，使底部入口更贴近参考图的轻量二级菜单风格。

### Out Of Scope

- 不新增或修改任何 Rust command。
- 不修改 Gateway 会话协议、返回字段或 `invoke()` 调用。
- 不修改 `selectSession(...)`、聊天发送、历史持久化或渠道绑定逻辑。
- 不重做整个目录卡片结构，只收敛最近会话二级菜单的展示行为。

## Implementation Notes

### Data shaping

- 复用现有 `sessionsResult`、`historyTitleCache` 和 `buildSessionHistoryItem(...)`。
- 每个 agent 只保留最近 7 条会话预览，按最近更新时间倒序排序。
- 目录默认只渲染前 3 条；“更多”逻辑只作用于前端显示层，不改变真实 session 数据源。

### Directory rendering

- 数字员工主卡片继续复用原有点击行为，保持进入主会话的语义不变。
- 最近会话二级菜单继续复用现有 `onSelectSession(sessionKey, agentId)` 切换逻辑。
- “展开更多 / 收起更多”状态仅保存在目录本地 UI state 中，按 `agentId` 维度记录。

## Validation

1. 当某个数字员工只有 0 到 3 条最近会话时，目录直接展示全部会话，不出现“展开更多”。
2. 当最近会话大于 3 条时，目录默认只展示前 3 条，底部显示“展开更多”。
3. 点击“展开更多”后，最多展示 7 条最近会话；若总数不足 7 条，则展示全部可用数据。
4. 展开态底部按钮文案切换为“收起更多”，点击后恢复为只展示 3 条。
5. 点击主卡片和点击二级会话项的行为保持原有语义，不新增 `invoke()` 或 Gateway 协议改动。
6. 提交前执行：
   - `npm run check:encoding`
   - `npm run check:file-size`
   - `npm run tauri dev`
