# Phase 5.13: 按截图收敛聊天工作区 UI

> 状态：规划中
> 类型：前端界面优化
> 前置阶段：Phase 5.10 默认首页壳层克隆、Phase 5.12 聊天工作区 UI 克隆

## 目标

以用户提供的截图为直接视觉目标，对默认首页 `workspace-clone` 下的 `聊天` 工作区做一次进一步收敛。

本轮重点不再是“轻量三栏”这个抽象方向，而是把默认态尽量拉回到图 1：

- 三栏是同一工作台内的轻分栏，而不是三张厚卡片
- 聊天主区默认只有一条欢迎消息和大面积留白
- 建议卡更轻、更矮、更像快捷入口
- 输入区回到图 1 的单层大输入盒结构
- 右侧详情抽屉保留，但默认隐藏，不抢占首页第一屏

## 视觉基准

### 默认态基准

默认首页只以图 1 为基准，不再以图 2 作为首页主布局参考。

这意味着：

- 首页打开时必须先接近图 1
- 右侧抽屉只能作为二级交互出现
- 图 2 里的重卡片感、厚边框、大块消息卡都要明显回退

### 允许保留的二级能力

- 右上角图标入口
- 右侧详情抽屉
- 相关 overlay / modal
- 目录区和侧栏的本地开合交互

上述能力允许继续存在，但不能影响图 1 默认态的整体观感。

## 本次范围

### 包含

- `聊天` 菜单对应首页默认态的重新收敛
- 左侧栏、目录栏、聊天头部、聊天画布、建议卡、输入区的视觉减重
- 右侧详情抽屉默认关闭的交互策略
- `workspace-clone` 聊天链路相关组件中的乱码中文清理
- 默认态文案收敛为更短、更轻的首页文本
- 输入区去除顶部“发送给…”提示和工具栏上方分隔线，减少视觉噪音

### 不包含

- 新的 Tauri / Rust 命令
- 任何 `invoke()` 名称、参数、返回类型调整
- `useService / useConfig / useSetup / useLogs` 业务逻辑修改
- legacy `dashboard`、legacy top-tab shell 删除
- `聊天` 以外菜单的深度重绘

## 收敛原则

- 三栏从“卡片并列”改成“分栏布局”，优先使用分隔线、浅底色和弱圆角
- 聊天主区默认只保留一条欢迎消息，不再让消息卡成为主视觉
- 副标题、说明文案、建议卡文案统一缩短
- 默认界面里的模型、Provider、日志、工作区路径等信息退回到抽屉或弹层
- 抽屉打开态不再作为首页主参考，只要求不破坏默认态

## 交互约束

- 默认首页不显示右侧详情抽屉
- 抽屉只通过右上角图标打开
- 首页默认态尽量不出现厚重消息卡、额外说明块和第二条系统提示
- 顶部 icon controls 保留，但样式更轻、更弱、更贴近截图
- 现有 overlay / modal 保留职责，但默认关闭
- 输入区保留单层容器结构，不再额外显示字段标题式提示

## 验收标准

- 默认首页进入 `workspace-clone > 聊天` 后，第一眼接近图 1，而不是当前图 2
- 三栏是轻分栏，不再像三张独立大卡片
- 聊天主区默认只有一条欢迎消息和大面积留白
- 建议卡数量、位置和轻量感接近图 1
- 输入区为单层大输入盒，控件分布接近图 1
- 输入区顶部不再显示“发送给…”提示，工具栏与文本区之间不再出现额外分隔线
- 右侧详情抽屉默认不显示，只能通过右上角入口打开
- 所有聊天主链路中文文案无乱码
- 其他菜单骨架、legacy 页面和现有业务逻辑不回归

## 遗留说明

以下内容本次继续保留为后续迁移对象：

- legacy `dashboard` 页面
- legacy top-tab shell
- 现有真实业务 hooks 与弹窗逻辑
- `聊天` 以外菜单的深层界面

待本轮默认态收敛稳定后，再继续评估真实功能迁移与旧假 UI 清理。
