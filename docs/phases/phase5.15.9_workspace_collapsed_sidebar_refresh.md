# Phase 5.15.9: 首页收缩侧边栏视觉重设计

> 状态：规划中
> 类型：前端 UI 重设计
> 前置阶段：Phase 5.15.3 / Phase 5.15.8

## 目标

围绕 `workspace-clone` 首页的收缩态导航，对左侧主菜单轨和右侧迷你目录轨做一次成套视觉重设计，让整体观感更接近参考图中的“浅色双竖栏 + 悬浮卡片按钮”形态。

本次改造只处理前端 `.tsx` / `.css` 的渲染层和样式层，不调整任何 `invoke()` 调用、事件处理逻辑、hooks 业务实现或 Rust 后端命令。

## 本次范围

- 保留现有收缩/展开交互语义，不改变 `isSidebarCollapsed` 与 `isDirectoryCollapsed` 的状态流
- 保留第二栏展开态的三类目录入口：`数字员工 / 频道 / 团队`
- 重做左侧收缩菜单轨的顶部按钮、主菜单按钮、底部品牌区和操作区视觉样式
- 重做右侧迷你目录轨的顶部按钮、类型入口和实体头像按钮的布局与卡片节奏
- 统一收缩态的圆角、边框、投影、留白、选中态和 hover 态
- 让桌面端默认收缩样式与中等宽度断点下的自动迷你轨保持一致的视觉方向

## 不包含

- 不新增或删除任何菜单项、目录项、Agent 数据源和业务入口
- 不修改 `WorkspaceClonePage` 中与 gateway、memory、skills、tools 相关的业务逻辑
- 不处理展开态目录的信息架构重构
- 不接入新的图片资源、后端接口或配置项

## 关键设计

### 1. 左侧菜单轨

- 收缩态宽度继续控制在轻量窄栏范围内
- 顶部折叠按钮采用悬浮白卡风格，与主菜单按钮形成一致组件语言
- 主菜单按钮改为更明确的竖向节奏，选中项强化柔和描边与浅蓝高亮
- 底部品牌位弱化为轻量水印，避免与主导航争抢视觉焦点

### 2. 右侧迷你目录轨

- 迷你目录轨采用独立浅底与内边距，形成与左轨并列的第二层导航
- 顶部保留目录展开和新建占位入口，但统一为悬浮卡片按钮组
- 类型入口与实体头像改为纵向卡片堆叠，突出“快捷切换当前 Agent / 目录项”的使用感
- 当前选中实体继续通过 `selectedEntityId` 驱动，只调整表现形式

### 3. 视觉约束

- 保持现有浅色主题变量，不引入新的功能状态
- 优先通过已有 `workspace-clone` 类名扩展样式，避免扩散到 legacy 页面
- 兼顾 `max-width: 1280px` 自动迷你轨与移动端单列断点，防止桌面改造影响移动布局

## 验收标准

- 首页在侧边栏和目录都收缩时，整体观感接近参考图中的双轨浅色导航
- 第二栏在展开态下可见 `数字员工 / 频道 / 团队` 三类入口，收缩态也能切换对应迷你轨
- 左侧菜单轨的顶部按钮、菜单项、底部操作按钮形成统一白卡组件语言
- 左侧菜单轨的收起/展开按钮贴靠在侧栏与目录栏之间的边线上，避免悬浮在栏内造成视觉偏移
- 右侧迷你目录轨的入口与头像按钮具有更清晰的层次、留白和选中反馈
- 仅修改 `workspace-clone` 相关 `.tsx` / `.css`，不引入 `invoke()`、hooks 或 Rust 逻辑回归
- `npm run build` 可通过，且未出现新的 TypeScript / CSS 引用错误
