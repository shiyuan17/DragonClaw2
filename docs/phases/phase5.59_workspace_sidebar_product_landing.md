# Phase 5.59: Workspace 侧边栏产品落地项开放

> 状态：规划中
> 类型：前端 UI 落地 / 信息架构补齐

## 目标

在 `workspace-clone` 左侧侧边栏中正式开放 `产品落地` 菜单项，去掉当前弱化占位态，并为该入口提供一个独立的前端落地页骨架。此次改动只处理 React 渲染层与样式层，不改动任何 `invoke()`、Gateway、cron、聊天发送或后端接口契约。

## 本次范围

- 保留现有 `WorkspaceMenuKey = "tasks"` 与侧边栏选择逻辑，不新增、不删除菜单 key。
- 去掉 `WorkspaceCloneSidebar` 中对 `tasks` 菜单的特殊弱化表现，让 `产品落地` 与其他正式菜单共享同一套 hover / active 反馈。
- 修正侧边栏内本次触达的高曝光错码文案，包括：
  - 主菜单文案
  - 侧边栏折叠按钮提示
  - 底部身份卡与设置弹层文案
- 新增 `产品落地` 专属内容视图，替代当前复用 `WorkspaceCloneCompactView` 的通用占位面板。
- 落地页以“能力分区 + 示例场景 + 当前边界”形式呈现，作为后续真实能力接入前的清晰骨架。
- 仅扩展 `workspace-clone` 相关 `.tsx` / `.css`，并优先复用现有 `--dc-workspace-*` token。

## 不包含

- 不改 `useWorkspaceGatewayChat`、`useWorkspaceCronTasks`、`WorkspaceCloneComposer` 等业务 hooks。
- 不接入真实任务执行、真实产品工作流、文件上传、表单提交流程或任何新后端命令。
- 不修改 `tasks` 对应的 Tauri command、Gateway 数据结构或 `invoke()` 参数/返回值。
- 不顺带重构其他 workspace 页面或大范围清理全仓乱码。

## 关键设计

### 1. 入口状态

- `产品落地` 不再表现为灰化占位项。
- 展开态与收缩态都应拥有与其他菜单一致的可点击反馈。

### 2. 落地页结构

- 顶部 hero：说明这是一个“产品落地能力中心”，强调当前是可浏览、可规划、待逐步接入真实执行能力的状态。
- 中部能力卡片：按典型落地方向展示若干分区，例如自动化任务、文件整理、社媒运营、本地生活、教育学习。
- 侧边说明：展示当前可承接的工作方式、推荐使用路径和当前边界，避免用户误以为所有能力已经打通。

### 3. 视觉约束

- 延续 ElevenLabs token 体系，不引入独立子主题。
- 风格上与 `workspace-clone` 现有浅色玻璃面板保持统一，但让 `产品落地` 页比通用占位更完整、更像真实工作台入口。

## 验收标准

- 左侧侧边栏的 `产品落地` 菜单项不再是 muted 态，hover / active 反馈与其他正式菜单一致。
- 点击 `产品落地` 后，主区显示专属落地页，而不是通用 compact 占位页。
- 侧边栏本次涉及的高曝光文案不再出现错码。
- 仅修改 `workspace-clone` 前端渲染层与样式层，不改任何 Tauri / `invoke()` / Gateway 契约。
- `npm run build` 可通过，且没有新的 TypeScript / CSS 引用错误。

## 假设

- 本轮“开放”解释为：从弱化占位入口升级为正式可见入口，并补齐独立前端骨架，而不是在本轮直接接入真实产品执行链路。
- 现有聊天、任务抽屉、目录栏和设置弹层行为保持不变，本轮只调整视觉层与内容编排。
