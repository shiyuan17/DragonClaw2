# Phase 5.59: Workspace 侧边栏产品落地项开放
> 状态：进行中
> 类型：前端 UI 落地 / 信息架构补齐

## 目标

在 `workspace-clone` 左侧侧边栏中正式开放 `产品落地` 菜单项，去掉弱化占位态，并把主区升级成一个更完整的产品交付入口页。本轮继续限定在 React 渲染层和样式层：同步 DragonClaw 原版产品落地页中的交付项、优化排版层级和视觉节奏，不改动任何 `invoke()`、Gateway、cron、聊天发送或后端接口契约。

## 本次范围

- 保留现有 `WorkspaceMenuKey = "tasks"` 与侧边栏选择逻辑，不新增、不删除菜单 key。
- 维持 `产品落地` 为前端信息入口，不接入真实执行流，不新增表单或上传动作。
- 同步 DragonClaw 原版产品落地页里的常见交付方向，包括独立站、绘本、PPT、小程序、游戏原型、短视频、小红书图文、公众号文章。
- 把页面从单列占位卡片升级为 `hero + 卡片矩阵 + 侧栏说明` 的正式入口布局。
- 只修改 `workspace-clone` 相关 `.tsx` / `.css`，并优先复用现有 `--dc-*` 与 `--dc-workspace-*` token。

## 不包含

- 不改 `useWorkspaceGatewayChat`、`useWorkspaceCronTasks`、`WorkspaceCloneComposer` 等业务 hooks。
- 不接入真实任务执行、真实产品工作流、文件上传、表单提交流程或任何新后端命令。
- 不修改 `tasks` 对应的 Tauri command、Gateway 数据结构或 `invoke()` 参数 / 返回值。
- 不顺带重构其他 workspace 页面。

## 关键设计

### 1. 页面结构

- 顶部 hero 负责说明这是“产品落地能力中心”，强调当前以浏览、规划和能力编排为主。
- 中部主区采用多列卡片矩阵展示同步后的 8 个交付方向，每张卡片保留标题、描述和 3 个标签。
- 右侧说明栏用于承接推荐推进方式、当前同步范围和边界提醒，避免用户误以为所有交付能力已经接通真实执行链路。

### 2. 视觉方向

- 继续沿用 ElevenLabs token 体系，不引入独立子主题。
- 页面需要比通用 placeholder 更像正式工作台入口：增强首屏层级、补足背景气氛、压缩空白比例。
- 卡片色调通过现有设计 token 做轻量区分，避免重新发明第二套视觉系统。

### 3. 内容同步原则

- 以 DragonClaw 原版产品落地页的交付类型为准同步主卡片项。
- 当前 `workspace-clone` 中更偏“场景模板”的旧卡片文案不再作为主列表保留。
- 文案保持中文可读、UTF-8 正常，不引入新的乱码字符串。

## 验收标准

- 点击 `产品落地` 后，主区展示的是专属产品落地页，而不是通用 compact 占位页。
- 页面能看到同步后的 8 个产品交付方向，而不是当前的 4 个简化场景卡片。
- 首屏排版明显收敛为空间更均衡的 hero + 卡片矩阵 + 侧栏说明布局，右侧不再大面积留白。
- 仅修改 `workspace-clone` 前端渲染层与样式层，不改任何 Tauri / `invoke()` / Gateway 契约。
- 编码检查通过，且没有新增 TypeScript / CSS 引用错误。

## 假设

- 本轮“同步 DragonClaw 中的其他项”解释为同步旧仓库产品交付卡片的数据结构与信息层级，而不是迁移真实业务能力。
- 用户期望的是先把产品落地页做成一个更完整的前端入口，再决定后续是否逐项接入真实链路。
