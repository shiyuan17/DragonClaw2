# Phase 5.67: Workspace 技能库弹窗缓存

> 状态：规划中
> 类型：前端体验优化
> 前置阶段：Phase 5.15.6 skills 弹窗接入、Phase 5.21 技能市场同步

## 目标

为 `workspace-clone > chat > 技能库` 弹窗补齐前端缓存，让用户在同一轮会话里重复打开同一个 Agent 的技能库时不再每次都看到“正在加载技能配置”，而是优先显示最近一次成功加载的列表与勾选状态。

## 范围

### 本次包含

- 在 `useWorkspaceSkillsAdmin` 内按 `agentId` 维护技能列表快照缓存
- 首次打开无缓存时保持当前真实加载行为
- 已有缓存时优先渲染缓存，再按需静默回刷
- 显式点击“刷新”时仍走真实刷新，并覆盖缓存
- 保存技能配置成功后继续以真实返回结果回刷缓存

### 本次不包含

- 不改动 `get_agent_skill_config`、`save_agent_skill_config`、`list_skills` 或 `skills.status` 的接口契约
- 不改动技能市场页、安装链路或后端缓存
- 不改动技能弹窗的筛选、分类、勾选和保存语义

## 关键设计

### 1. 缓存粒度

- 缓存以 `agentId` 为 key
- 每份快照至少包含：
  - `WorkspaceSkillOption[]`
  - 当前已选 `skillDraftIds`
  - 最近成功加载时间

### 2. 打开策略

- 若当前 Agent 没有缓存：保持现状，显示加载态并发起真实请求
- 若当前 Agent 有缓存且仍在 TTL 内：直接展示缓存，不额外阻塞打开
- 若当前 Agent 有缓存但已过期：先展示缓存，再静默刷新

### 3. 刷新策略

- 手动刷新：保留显式加载态，确保用户知道正在回刷
- 保存成功后的内部刷新：无需额外遮罩，但必须更新缓存
- 切换 Agent：按新 `agentId` 独立命中或失效缓存，不复用别的 Agent 快照

## 验收标准

- 同一个 Agent 重复打开技能库时，若已有缓存，不再每次显示等待态
- 首次打开或缓存缺失时，仍能正确加载真实技能列表
- 手动刷新后，列表内容与缓存同步更新
- 保存技能配置后，再次打开弹窗可以立即看到最新快照
- 不影响现有 `invoke()`、Gateway、技能市场安装回刷和技能保存行为
