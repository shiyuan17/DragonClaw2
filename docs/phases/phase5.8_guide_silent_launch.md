# Phase 5.8: 引导流程静默自动启动

> 状态：已实现，待验收

## 目标

在 Launcher 完成环境检查、初始化和工作区配置后，由引导流程自动启动 OpenClaw 服务，并且这次引导启动不自动打开 OpenClaw 浏览器页面。对于首次无配置用户，直接落地默认工作区与默认模型，整个引导过程尽量零点击，服务与推荐技能安装完成后立即进入主界面。

## 设计原则

- 保留主界面的启动/停止、托盘与打开浏览器逻辑不变，只修正引导阶段的前端编排。
- 不修改任何现有 Tauri command 签名，不破坏 `invoke()` 契约。
- 复用现有 `start_service_silent` 静默启动入口，不新增新的前后端接口。
- `workspace` 阶段继续保留，但仅作为默认工作区自动配置失败时的人工兜底。

## 实现方案

1. 引导主路径统一走 `launching`：
   - 环境完整、配置存在但服务未运行时直接进入 `launching`。
   - 首次无配置时，先自动执行 `inject_default_config({ workspacePath: null })`、`inject_default_models()` 与 onboarding state 写入，再进入 `launching`。
   - 只有默认工作区自动配置失败时，才回退到 `workspace` 阶段让用户手动选目录。

2. `useSetup` 统一编排静默启动与收尾：
   - 调用现有 `start_service_silent`，监听服务 ready 日志后执行统一收尾。
   - 服务已运行、首次初始化完成、工作区手动确认完成三条路径都汇合到同一套 `finalizeStartup()`。
   - 推荐技能安装完成后立即 `phase=ready`，不再额外停留成功页，也不等待点击。

3. `SetupWizard` 结构保持不变：
   - `checking / initializing / launching` 仍然是默认主流程。
   - `workspace` 仅作为异常恢复路径保留。
   - 启动页只显示准备、启动、推荐技能安装等自动进度，不增加新的收尾按钮。

## 验收标准

- 环境和配置已就绪但服务未运行时，打开 Launcher 会自动启动服务，不打开浏览器。
- 首次无 `openclaw.json` 时，会自动写入默认工作区和默认模型，并直通主界面。
- 默认工作区自动配置失败时，不死循环重试，而是回退到工作区选择页。
- 推荐技能安装完成后立即进入主界面；若其中部分安装失败，仍保持当前容错语义继续进入主界面。
- 主界面的启动/停止按钮、访问控制台按钮、托盘打开浏览器行为保持原样。
